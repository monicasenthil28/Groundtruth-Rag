# Retrieval Experiments

The versioned [OSHA specification](../experiments/osha/retrieval-v1.yaml) names one fixed benchmark, its aggregate and query baselines, a regression policy, Pareto dimensions, and a small set of candidates. Each candidate starts from a canonical benchmark config. Only positive integer `rrf_k`, `dense_candidates`, `bm25_candidates`, and `candidate_pool` overrides are accepted where the retriever type supports them. Unknown fields, changed types, duplicate IDs, and duplicate resolved configurations fail validation. Model identifiers are inherited from canonical configs, not entered through experiment overrides.

Run `groundtruth experiment-run experiments/osha/retrieval-v1.yaml --output reports/experiments/osha/retrieval-v1 --dry-run` first. This verifies corpus fingerprint, manifest, dataset hash and labels, baseline identities, policy, and resolved configs without loading models or writing reports. Actual execution evaluates candidates on the same corpus and human labels, writes ordinary run JSON plus regression and query diagnostics, then produces `experiment.json` and `EXPERIMENT.md` under `reports/experiments/`. These are local artifacts, not committed inputs.

Each run records the experiment and candidate IDs, resolved config and hash, base config path and file hash, corpus and dataset hashes, benchmark spec version, model IDs, Python and package versions, dependency versions, and timestamps. Full run JSON contains evaluation questions but no source passages. The top-level experiment report contains aggregates and decision evidence only.

Pareto comparison uses selected higher-is-better quality metrics and optionally lower-is-better p95 latency. A candidate is dominated only when another is at least as good on every included dimension and strictly better on one. Latency is environment-sensitive; the first OSHA experiment excludes it from Pareto and leaves latency regression gating to the existing policy. There is no weighted composite score. A `--candidate` subset run cannot establish a full frontier and is marked `NOT_EVALUATED` for Pareto; it cannot receive `PROMOTE_CANDIDATE`.

`REJECT` means aggregate or enabled query gate FAIL. `REVIEW` covers WARN, newly lost critical queries when configured, Pareto domination, optional latency review, or a partial candidate set. `PROMOTE_CANDIDATE` means a complete run satisfies the configured checks. It is advisory: the tool never replaces a canonical config, baseline, corpus, or golden label, and never deploys. Four-stage failure forensics requires four compatible stage runs; a single candidate run is explicitly marked unavailable rather than mixed with older runs.

Chunk size and overlap are excluded because changing chunk IDs would invalidate the existing human relevance judgments. The framework does not search parameters, download arbitrary user-selected models, score generated answers, or claim statistical significance.

Saved candidate runs may be compared to their original same-family benchmark runs with `groundtruth robustness-analyze`. This produces separate advisory quality evidence under `reports/robustness/`; it does not alter `experiment.json`, regression statuses, Pareto status, or promotion decisions. Optional `groundtruth latency-trials` measures repeated executions of one validated experiment candidate. See [robustness analysis](ROBUSTNESS.md).

`PROMOTE_CANDIDATE` remains a review recommendation. It does not write a canonical config or make a version active. Versioned promotion uses a separate manifest, explicit human approval, isolated validation benchmark, generated baseline pair, and registry switch. See [promotion](PROMOTION.md).
